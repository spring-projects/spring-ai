= Weaviate
:page-aliases: api/vectordbs/weaviate.adoc

This section walks you through setting up the Weaviate VectorStore to store document embeddings and perform similarity searches.

link:https://weaviate.io/[Weaviate] is an open-source vector database that allows you to store data objects and vector embeddings from your favorite ML-models and scale seamlessly into billions of data objects.
It provides tools to store document embeddings, content, and metadata and to search through those embeddings, including metadata filtering.

== Prerequisites

* A running Weaviate instance.
The following options are available:
** link:https://console.weaviate.cloud/[Weaviate Cloud Service] (requires account creation and API key)
** link:https://weaviate.io/developers/weaviate/installation/docker[Docker container]
* If required, an API key for the xref:models/embeddings.adoc#available-implementations[EmbeddingModel] to generate the embeddings stored by the `WeaviateVectorStore`.

[NOTE]
====
The Weaviate Vector Store is built on the Weaviate Java `client6` API and uses gRPC for similarity search, writes, and deletes.
This means:

* The Weaviate server must expose its gRPC endpoint (port `50051` by default) in addition to the HTTP endpoint (port `8080` by default).
* GraphQL does not need to be enabled on the cluster.
* A recent Weaviate server version that supports the gRPC API is required (for example `1.31.22`, used in the examples below).

Applications that previously constructed a v5 `io.weaviate.client.WeaviateClient` must migrate to the `client6` `io.weaviate.client6.v1.api.WeaviateClient`.
See <<Migrating from the Weaviate v5 client>> below.
====

== Dependencies

Add the Weaviate Vector Store dependency to your project:

[source,xml]
----
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-weaviate-store</artifactId>
</dependency>
----

or to your Gradle `build.gradle` build file.

[source,groovy]
----
dependencies {
    implementation 'org.springframework.ai:spring-ai-weaviate-store'
}
----

TIP: Refer to the xref:get-started/project-setup.adoc#dependency-management[Dependency Management] section to add the Spring AI BOM to your build file.

== Configuration

To connect to Weaviate and use the `WeaviateVectorStore`, you need to provide access details for your instance.
Configuration can be provided via Spring Boot's _application.properties_:

[source,properties]
----
spring.ai.vectorstore.weaviate.host=<host_of_your_weaviate_instance>
spring.ai.vectorstore.weaviate.scheme=<http_or_https>
spring.ai.vectorstore.weaviate.api-key=<your_api_key>
# Optional gRPC coordinates. grpc-host defaults to the host above, grpc-port defaults to 50051.
spring.ai.vectorstore.weaviate.grpc-host=<grpc_host_of_your_weaviate_instance>
spring.ai.vectorstore.weaviate.grpc-port=50051
# API key if needed, e.g. OpenAI
spring.ai.openai.api-key=<api-key>
----

NOTE: The `client6` driver connects over both HTTP and gRPC.
When your Weaviate server exposes gRPC on a non-default host or port (for example behind a proxy or on a mapped container port), set `grpc-host` and `grpc-port` accordingly.
For Weaviate Cloud, the gRPC endpoint is served over TLS on the same domain; set `scheme=https`.

If you prefer to use environment variables for sensitive information like API keys, you have multiple options:

=== Option 1: Using Spring Expression Language (SpEL)

You can use custom environment variable names and reference them in your application configuration:

[source,yaml]
----
# In application.yml
spring:
  ai:
    vectorstore:
      weaviate:
        host: ${WEAVIATE_HOST}
        scheme: ${WEAVIATE_SCHEME}
        api-key: ${WEAVIATE_API_KEY}
    openai:
      api-key: ${OPENAI_API_KEY}
----

[source,bash]
----
# In your environment or .env file
export WEAVIATE_HOST=<host_of_your_weaviate_instance>
export WEAVIATE_SCHEME=<http_or_https>
export WEAVIATE_API_KEY=<your_api_key>
export OPENAI_API_KEY=<api-key>
----

=== Option 2: Accessing Environment Variables Programmatically

Alternatively, you can access environment variables in your Java code:

[source,java]
----
String weaviateApiKey = System.getenv("WEAVIATE_API_KEY");
String openAiApiKey = System.getenv("OPENAI_API_KEY");
----

NOTE: If you choose to create a shell script to manage your environment variables, be sure to run it prior to starting your application by "sourcing" the file, i.e. `source <your_script_name>.sh`.

== Auto-configuration

Spring AI provides Spring Boot auto-configuration for the Weaviate Vector Store.
To enable it, add the following dependency to your project's Maven `pom.xml` file:

[source,xml]
----
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-vector-store-weaviate</artifactId>
</dependency>
----

or to your Gradle `build.gradle` build file.

[source,groovy]
----
dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-vector-store-weaviate'
}
----

TIP: Refer to the xref:get-started/project-setup.adoc#dependency-management[Dependency Management] section to add the Spring AI BOM to your build file.

Please have a look at the list of xref:#_weaviatevectorstore_properties[configuration parameters] for the vector store to learn about the default values and configuration options.

TIP: Refer to the xref:get-started/project-setup.adoc#artifact-repositories[Artifact Repositories] section to add Maven Central and/or Snapshot Repositories to your build file.

Additionally, you will need a configured `EmbeddingModel` bean.
Refer to the xref:models/embeddings.adoc#available-implementations[EmbeddingModel] section for more information.

Here is an example of the required bean:

[source,java]
----
@Bean
public EmbeddingModel embeddingModel() {
    // Retrieve API key from a secure source or environment variable
    String apiKey = System.getenv("OPENAI_API_KEY");

    // Can be any other EmbeddingModel implementation
    return new OpenAiEmbeddingModel(OpenAiEmbeddingOptions.builder().apiKey(apiKey).build());
}
----

Now you can auto-wire the `WeaviateVectorStore` as a vector store in your application.

== Manual Configuration

Instead of using Spring Boot auto-configuration, you can manually configure the `WeaviateVectorStore` using the builder pattern:

The `WeaviateClient` is the `client6` type `io.weaviate.client6.v1.api.WeaviateClient`.

[source,java]
----
@Bean
public WeaviateClient weaviateClient() {
    // Local instance with default ports (HTTP 8080, gRPC 50051):
    return WeaviateClient.connectToLocal();

    // Or, for a custom endpoint:
    // return WeaviateClient.connectToCustom(custom -> custom.scheme("http")
    //     .httpHost("localhost").httpPort(8080)
    //     .grpcHost("localhost").grpcPort(50051));

    // Or, for Weaviate Cloud:
    // return WeaviateClient.connectToWeaviateCloud("my-cluster.weaviate.cloud", "<api-key>");
}

@Bean
public VectorStore vectorStore(WeaviateClient weaviateClient, EmbeddingModel embeddingModel) {
    return WeaviateVectorStore.builder(weaviateClient, embeddingModel)
        .options(options)                              // Optional: use custom options
        .consistencyLevel(ConsistentLevel.QUORUM)      // Optional: defaults to ConsistentLevel.ONE
        .filterMetadataFields(List.of(                 // Optional: fields that can be used in filters
            MetadataField.text("country"),
            MetadataField.number("year")))
        .build();
}
----

NOTE: The `client6` `WeaviateClient` is `AutoCloseable` and connects eagerly when constructed, so the Weaviate server must be reachable at bean-creation time.
When you create the client yourself, let Spring manage its lifecycle (for example `@Bean(destroyMethod = "close")`).

== Metadata filtering

You can leverage the generic, portable xref:rag/vector-store/filters.adoc[metadata filters] with Weaviate store as well.

For example, you can use either the text expression language:

[source,java]
----
vectorStore.similaritySearch(
    SearchRequest.builder()
        .query("The World")
        .topK(TOP_K)
        .similarityThreshold(SIMILARITY_THRESHOLD)
        .filterExpression("country in ['UK', 'NL'] && year >= 2020").build());
----

or programmatically using the `Filter.Expression` DSL:

[source,java]
----
FilterExpressionBuilder b = new FilterExpressionBuilder();

vectorStore.similaritySearch(SearchRequest.builder()
    .query("The World")
    .topK(TOP_K)
    .similarityThreshold(SIMILARITY_THRESHOLD)
    .filterExpression(b.and(
        b.in("country", "UK", "NL"),
        b.gte("year", 2020)).build()).build());
----

NOTE: Those (portable) filter expressions are automatically converted into native Weaviate `client6` `Filter` objects and applied over gRPC.
No GraphQL filter strings are produced.

For example, the portable filter expression `country in ['UK', 'NL'] && year >= 2020` is converted into the structured filter `(meta_country == "UK" OR meta_country == "NL") AND meta_year >= 2020`, where the filterable metadata fields are prefixed (by default with `meta_`).

== Run Weaviate in Docker

To quickly get started with a local Weaviate instance, you can run it in Docker:

[source,bash]
----
docker run -it --rm --name weaviate \
    -e AUTHENTICATION_ANONYMOUS_ACCESS_ENABLED=true \
    -e PERSISTENCE_DATA_PATH=/var/lib/weaviate \
    -e QUERY_DEFAULTS_LIMIT=25 \
    -e DEFAULT_VECTORIZER_MODULE=none \
    -e CLUSTER_HOSTNAME=node1 \
    -p 8080:8080 \
    -p 50051:50051 \
    semitechnologies/weaviate:1.31.22
----

This starts a Weaviate instance with the HTTP endpoint accessible at http://localhost:8080 and the gRPC endpoint at `localhost:50051`.
The gRPC port must be published because the store performs all queries, writes, and deletes over gRPC.

== WeaviateVectorStore properties

You can use the following properties in your Spring Boot configuration to customize the Weaviate vector store.

[stripes=even]
|===
|Property|Description|Default value

|`spring.ai.vectorstore.weaviate.host`|The HTTP host of the Weaviate server, in `host:port` form|localhost:8080
|`spring.ai.vectorstore.weaviate.scheme`|Connection schema (`http` or `https`); `https` enables TLS|http
|`spring.ai.vectorstore.weaviate.grpc-host`|The gRPC host. When empty, defaults to the host part of `host`|
|`spring.ai.vectorstore.weaviate.grpc-port`|The gRPC port|50051
|`spring.ai.vectorstore.weaviate.api-key`|The API key for authentication|
|`spring.ai.vectorstore.weaviate.object-class`|The class name for storing documents. |SpringAiWeaviate
|`spring.ai.vectorstore.weaviate.content-field-name`|The field name for content|content
|`spring.ai.vectorstore.weaviate.meta-field-prefix`|The field prefix for metadata|meta_
|`spring.ai.vectorstore.weaviate.consistency-level`|Desired tradeoff between consistency and speed|ConsistentLevel.ONE
|`spring.ai.vectorstore.weaviate.filter-field`|Configures metadata fields that can be used in filters. Format: spring.ai.vectorstore.weaviate.filter-field.<field-name>=<field-type>|
|===

TIP: Object class names should start with an uppercase letter, and field names should start with a lowercase letter.
See link:https://weaviate.io/developers/weaviate/concepts/data#data-object-concepts[data-object-concepts]

== Collection and schema

On first use, the store ensures its collection (`object-class`) exists.
If the collection is missing, it is created with a self-provided (vectorizer: `none`, bring-your-own-vector) index configured for *cosine* distance, a text content property, a text `metadata` property, and one property per configured filterable metadata field.
An existing collection is reused as-is and is never reconfigured.

== Scoring and distance

Document scores are based on Weaviate's `certainty`, which is only meaningful for the *cosine* distance metric.
The store preserves `Document.score = certainty` and `DocumentMetadata.DISTANCE = 1 - certainty`.

IMPORTANT: Because `certainty` requires cosine distance, the store creates its collection with cosine distance.
If you point the store at a pre-existing collection that uses a different distance metric, `certainty` is not returned and similarity search fails fast with a clear error rather than returning silently incorrect scores.

== Consistency level

The `consistency-level` property (and the `consistencyLevel(...)` builder method) accepts `ONE`, `QUORUM`, or `ALL`, defaulting to `ONE`.

WARNING: Due to link:https://github.com/weaviate/java-client/issues/641[weaviate/java-client#641], the `client6` `6.3.0` driver currently maps both `QUORUM` and `ALL` to `ONE`.
When `QUORUM` or `ALL` is configured, the store logs a one-time warning.
This limitation will be removed once the project upgrades to a `client6` release that fixes the issue.

== Migrating from the Weaviate v5 client

Earlier versions of this store used the Weaviate Java v5 client and the GraphQL query API.
The store now uses the `client6` gRPC API. When upgrading:

* Replace the dependency `io.weaviate:client` with `io.weaviate:client6` (managed by the Spring AI BOM).
* Replace client construction `new io.weaviate.client.WeaviateClient(new Config(...))` with the `client6` `io.weaviate.client6.v1.api.WeaviateClient` (for example `WeaviateClient.connectToCustom(...)` or `WeaviateClient.connectToWeaviateCloud(...)`).
* Ensure the Weaviate server's gRPC endpoint (port `50051`) is reachable; GraphQL no longer needs to be enabled.
* `getNativeClient()` now returns `io.weaviate.client6.v1.api.WeaviateClient` (note the different package; both clients share the simple name `WeaviateClient`).
* The `WeaviateConnectionDetails` SPI now also exposes a gRPC endpoint via `getGrpcHost()` (a default method deriving `host:50051` from `getHost()`); custom implementations should override it when gRPC uses a different host or port.
* The `WeaviateFilterExpressionConverter` is now package-internal and produces `client6` `Filter` objects instead of GraphQL filter strings.

== Accessing the Native Client

The Weaviate Vector Store implementation provides access to the underlying native Weaviate client through the `getNativeClient()` method.
After the migration, this is the `client6` client `io.weaviate.client6.v1.api.WeaviateClient`:

[source,java]
----
import io.weaviate.client6.v1.api.WeaviateClient;

WeaviateVectorStore vectorStore = context.getBean(WeaviateVectorStore.class);
Optional<WeaviateClient> nativeClient = vectorStore.getNativeClient();

if (nativeClient.isPresent()) {
    WeaviateClient client = nativeClient.get();
    // Use the native client for Weaviate-specific operations
}
----

The native client gives you access to Weaviate-specific features and operations that might not be exposed through the `VectorStore` interface.
