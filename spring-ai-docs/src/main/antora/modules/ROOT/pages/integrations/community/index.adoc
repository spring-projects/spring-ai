[[community-support]]
== Support and Security

Community projects extend Spring AI with integrations and features beyond the core project, and many of them are well worth using.
They are maintained by their own authors, not by the Spring AI team, and come with different terms:

* *Support.* They are not covered by the Spring AI https://spring.io/support-policy[support policy] or by commercial support, and the Spring AI BOM does not manage their versions.
* *Security.* They are outside the https://spring.io/security-policy[Spring security policy]: each project handles vulnerability reports, fixes and disclosure itself, on its own schedule.
* *Versions.* Each project follows its own release schedule and versioning; a 0.x version can change its API between releases.
* *Compatibility.* Each release targets specific Spring AI versions: check the project's documentation before you upgrade either one.

Before you use a community project in production, evaluate it as you would any other third-party dependency: its release history, how active its issue tracker is, and how it handles security reports.
