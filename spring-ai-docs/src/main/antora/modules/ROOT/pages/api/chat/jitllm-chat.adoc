= jitLLM Chat

https://github.com/beehive-lab/jitllm[jitLLM] runs GGUF models in-process on the JVM, on the CPU or, through https://github.com/beehive-lab/TornadoVM[TornadoVM], on a GPU (CUDA, OpenCL or Metal).
It needs no server: the model is loaded from a local file and generation happens in your application's JVM.

== Prerequisites

* JDK 21 or newer. jitLLM uses the Vector API, so the JVM needs `--add-modules jdk.incubator.vector`.
* A model in GGUF format (FP16, Q8_0 or Q4_0) of a family jitLLM supports, such as Llama 3, Mistral, Qwen 2.5, Qwen 3, Phi-3, IBM Granite, Gemma 4 or DeepSeek-R1-Distill.
* For the GPU, a https://www.tornadovm.org/downloads[TornadoVM SDK] for your JDK line and your GPU's backend, also available through SDKMAN! (`sdk install tornadovm`).

jitLLM publishes one artifact per TornadoVM JDK line: `io.github.beehive-lab:jitllm:<version>-jdk22plus` for JDK 22 and newer, which the Spring AI modules depend on, and `<version>-jdk21` for JDK 21.
On JDK 21, replace the former with the latter and run with `--enable-preview`:

[source,xml]
----
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-jitllm</artifactId>
    <exclusions>
        <exclusion>
            <groupId>io.github.beehive-lab</groupId>
            <artifactId>jitllm</artifactId>
        </exclusion>
    </exclusions>
</dependency>
<dependency>
    <groupId>io.github.beehive-lab</groupId>
    <artifactId>jitllm</artifactId>
    <version>1.0.0-jdk21</version>
</dependency>
----

== Auto-configuration

Spring AI provides Spring Boot auto-configuration for the jitLLM Chat Model.
To enable it, add the following dependency to your project's Maven `pom.xml` file:

[source,xml]
----
<dependency>
    <groupId>org.springframework.ai</groupId>
    <artifactId>spring-ai-starter-model-jitllm</artifactId>
</dependency>
----

or to your Gradle `build.gradle` build file.

[source,groovy]
----
dependencies {
    implementation 'org.springframework.ai:spring-ai-starter-model-jitllm'
}
----

TIP: Refer to the xref:getting-started.adoc#dependency-management[Dependency Management] section to add the Spring AI BOM to your build file.

The chat model is created when `spring.ai.jitllm.chat.model-path` is set.

=== Chat Properties

The prefix `spring.ai.jitllm.chat` is the property prefix that configures the jitLLM chat model.

[cols="3,5,1", stripes=even]
|====
| Property | Description | Default

| spring.ai.model.chat | Enable the jitLLM chat model. | jitllm
| spring.ai.jitllm.chat.model-path | The GGUF model file to load. | -
| spring.ai.jitllm.chat.model-name | The model name reported in response metadata. | the model file name
| spring.ai.jitllm.chat.on-gpu | Run on a GPU through TornadoVM. The JVM must be started through TornadoVM's `tornado` launcher with `-Duse.tornadovm=true`; the backend is whichever one the SDK provides. | false
| spring.ai.jitllm.chat.context-length | The context length to allocate, in tokens; `0` uses the model's own. | 0
| spring.ai.jitllm.chat.max-tokens | The maximum number of tokens to generate. | 512
| spring.ai.jitllm.chat.temperature | The sampling temperature. | 0.1
| spring.ai.jitllm.chat.top-p | The nucleus sampling probability mass. | 0.95
| spring.ai.jitllm.chat.seed | The sampling seed. | -
| spring.ai.jitllm.chat.stop-sequences | Sequences that stop generation when they appear in the output. | -
|====

`topK`, `frequencyPenalty` and `presencePenalty` are accepted in `ChatOptions` but ignored: jitLLM's sampler does not support them.

TIP: All properties except `model-path`, `model-name`, `on-gpu` and `context-length`, which are fixed when the model is loaded, can be overridden per request with `JitLlmChatOptions`.

== Runtime Options [[chat-options]]

The link:https://github.com/spring-projects/spring-ai/blob/main/models/spring-ai-jitllm/src/main/java/org/springframework/ai/jitllm/JitLlmChatOptions.java[JitLlmChatOptions.java] class provides the per-request options:

[source,java]
----
ChatResponse response = chatModel.call(
    new Prompt(
        "Generate the names of 5 famous pirates.",
        JitLlmChatOptions.builder()
            .temperature(0.4)
            .maxTokens(256)
        .build()
    ));
----

== Tool Calling

jitLLM uses the model's own chat template to offer tools and to parse the calls it makes; see xref:api/tools.adoc[Tool Calling].
Forced tool choice and tools combined with a JSON response format are not supported.
When a request offers tools, a streaming call returns the response in a single chunk, because the calls are only known once generation ends.

== Thinking

For reasoning models such as Qwen 3, the content of `<think>` blocks is removed from the answer and returned in the assistant message's `thinking` metadata. Streamed chunks carry only the answer.

== Running on a GPU

Start the application through TornadoVM's launcher:

[source,bash]
----
tornado --jvm="-Duse.tornadovm=true --add-modules jdk.incubator.vector -Dtornado.device.memory=20GB" \
  -cp "target/classes:$(cat cp.txt)" com.example.Application
----

with `spring.ai.jitllm.chat.on-gpu=true`. Response metadata reports `on-gpu` and the prompt and generated token rates.

== Manual Configuration

The link:https://github.com/spring-projects/spring-ai/blob/main/models/spring-ai-jitllm/src/main/java/org/springframework/ai/jitllm/JitLlmChatModel.java[JitLlmChatModel] implements `ChatModel` and loads the model when it is built.
Add the `spring-ai-jitllm` dependency instead of the starter, and close the model when you are done with it:

[source,java]
----
try (JitLlmChatModel chatModel = JitLlmChatModel.builder()
        .modelPath(Path.of("/models/Qwen3-0.6B-F16.gguf"))
        .onGpu(true)
        .defaultOptions(JitLlmChatOptions.builder().temperature(0.2).build())
        .build()) {
    String answer = ChatClient.create(chatModel).prompt("Tell me a joke").call().content();
}
----
